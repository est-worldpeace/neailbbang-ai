# 내일의 빵 · 모델 비교 연구실

앱: https://naeil-bbang.vercel.app

저장소: https://github.com/SengangLemon/naeil-bbang (비공개)

기본 화면은 전체 비교 실험과 사용자가 정의한 최종 결합 모델의 평가입니다. 평가 구간·오차 지표·모델 계열을 선택하고, 모델별 종합 성적·102개 개별 실행·각 모델의 조건과 구간별 결과를 확인할 수 있습니다.

## Chronos-Bolt Small 비교

- `amazon/chronos-bolt-small` 공식 체크포인트를 CPU FP32로 실제 실행했습니다. 사전 고정 규칙은 `research/rebuild/chronos-protocol.json`, 실행 코드는 `chronos_benchmark.py`, 성공 실행은 https://github.com/SengangLemon/naeil-bbang/actions/runs/34934058491 입니다. 모델 가중치의 추가 학습은 없습니다.
- 이번 입력은 전날까지 최대 512개 달력일, 예측은 다음 하루입니다. 모델 지원 한도 2,048일과 실험 설정 512일은 다릅니다. 빠진 날짜는 NaN으로 유지했습니다. P50/P75는 공식 분위수 API에서 가져왔으며 P75 보간을 독립 재계산했습니다.
- 같은 974개 관측에서 원본 Chronos WAPE **26.6814%**, 가중 손실 **11,248**. 최근 56일 오차를 매일 보정하면 WAPE **26.9800%**, 손실 **11,185**입니다. 최종 사용자 모델은 WAPE **25.8157%**, 손실 **10,280**으로, 보정 Chronos보다 손실이 **8.09% 낮습니다**.
- 보정 Chronos − 사용자 모델 손실 차이 +905는 과다 +380 및 부족 +175의 3배로 구성됩니다. 14일 블록 95% 구간은 [92.775, 1681.05]입니다. 전체 점수는 사용자 모델이 우세하지만 11–12월 구간과 상품 82의 손실은 Chronos가 낮았습니다.
- Chronos 원본은 기존 일일 보정 후보 34개·사용자 모델에 자신을 추가한 36개 비교에서 WAPE 2위, 가중 손실 14위입니다. 보정 버전은 WAPE 4위·손실 14위입니다. 각각 별도로 순위를 계산하며, 두 보정 방식을 서로 다른 학습 모델로 세지 않습니다. 기존 102회 비교 결과는 그대로 보존했습니다.
- 1,297개 고유 입력 문맥에서 보정기간과 평가기간의 예측을 산출했습니다. `public/research/chronos/`에 원본 분위수·입력 날짜와 체크섬·일일 보정 기록, 5개 비교 방식의 4,870개 예측과 발표자료가 있습니다. `verify-chronos.cjs`는 내보낸 예측값에서 지표를 재계산하고 기존 참조·날짜 경계·순위를 확인합니다.
- 2024년에 공개된 모델로 2023년 자료를 평가한 후향 비교입니다. 사전학습에 이 공개 판매자료가 포함됐는지는 확인하지 못했습니다. 원본은 이번 자료로 가중치를 학습하지 않은 zero-shot, 보정 버전은 과거 오차에 적응한 결과입니다. 두 방식을 모두 보고하며 특정 설정의 결과를 시계열 사전학습 모델 전체의 우열로 일반화하지 않습니다.
- 발표자료: [PPT](https://naeil-bbang.vercel.app/research/chronos/chronos-comparison.pptx), [PDF](https://naeil-bbang.vercel.app/research/chronos/chronos-comparison.pdf). 앱 상단에서 기간별 비교와 함께 제공합니다. 운영 API에 Chronos 추론기를 추가한 것은 아닙니다.

## 날짜별 갱신 재평가

- 기본 화면은 **원설계의 주간 비중 갱신과 일일 잔차 갱신을 복원한 최종 모델**을, 다른 후보 34개도 매일 보정한 결과와 비교합니다. 비중까지 매일 갱신하는 변형과 이전 고정 모델, 후보의 고정/일일 보정을 전환할 수 있습니다.
- 같은 974개 상품·날짜를 비교했습니다. 기초 모델을 매일 재학습하지 않고 학습 외 원예측에 비중·잔차 보정을 적용합니다. 예측일 당일과 미래의 실적은 그 날짜 예측에 사용하지 않습니다. 이전 날짜의 확정 예측은 바꾸지 않습니다.
- 복원 모델 WAPE **25.8157%**, 과다 5,915, 부족 1,455, 가중 손실 **10,280**입니다. 이전 고정 구현 손실 12,481보다 **17.63% 감소**했습니다. 과다 자체는 937 늘고 부족이 1,046 줄었습니다. 실제 폐기 감소를 입증한 수치가 아닙니다.
- 복원 모델은 고정 후보 34개 및 일일 보정 후보 34개와 각각 비교했을 때 점수 1위입니다. 가장 좋은 일일 보정 후보와 손실 차이 -289의 7일/14일 묶음 부트스트랩 구간은 0을 포함하므로 확정적 우위를 주장하지 않습니다.
- 같은 초기조건의 2×2 진단에서 고정 11,116, 일일보정만 10,284, 주간비중만 10,905, 둘 다 10,280입니다. 주된 개선은 최근 오차자료 반영이며, 일일보정에 주간비중 갱신을 더한 4점 차이는 확실하지 않습니다. 세 통제 변형은 첫 결과를 본 뒤 기전 분리를 위해 추가한 탐색 분석입니다.
- `public/research/rolling/`에 77개 비교 계열 × 974개 관측 = 74,998개 예측, 7,792개 날짜별 갱신, 구간·상품별 지표와 불확실성을 저장합니다. 기존 35개 고정 결과는 그대로 보존합니다. 77개를 별도의 학습 알고리즘 수로 해석하지 않습니다.
- 새 재현 코드는 `research/rebuild/rolling_benchmark.py`, 별도 GitHub 실행은 `.github/workflows/rolling-benchmark.yml`입니다. 이전 GitHub 실행 `34814876448`의 보관된 학습 외 예측과 입력을 사용합니다. 보관 기간이 지난 경우 원학습 실행을 다시 만든 뒤 입력 경로를 지정해야 합니다.
- 빌드 전에 `verify-rolling.cjs`가 예측 CSV의 지표를 독립 재계산하고, 날짜별 갱신 기록의 시간 경계와 가중치 조건을 검증한 뒤 브라우저용 요약을 생성합니다. 발표자료는 앱 상단에서 PPT/PDF로 내려받을 수 있습니다.
- 이번 974건 재평가는 이전 대화의 970건 실험·체크포인트를 그대로 재현한 것이 아닙니다. 이전 WAPE 23.61%·손실 19,200은 원 대화에서 보고한 성적으로 구분합니다.

## 전체 비교 실험

- **34개 후보 설정 × 3개 시간순 구간 = 102회**, 사용자 최종 결합 모델 3회 추가 평가로 총 105개 실행 결과를 제공합니다. 102개의 서로 다른 알고리즘을 의미하지 않습니다.
- 이전 대화의 결과 파일이 없어 새로 재구성하고 학습한 실험입니다. 이전 대화에서 보고된 합산 성적은 화면 하단에 별도로 보존합니다.
- 공개 독일 빵집의 상품별 관측 판매수량을 사용합니다. 미기록일을 판매 0으로 가정하지 않습니다. 재고·미충족 수요·실제 폐기 정답이 없으므로 과다·부족과 3:1 가중 손실은 실제 폐기 감소나 금전 손실이 아닙니다.
- 각 구간은 학습 → 보정 → 평가 순서입니다. 하루 전까지의 정보만 특징에 사용하며, 구간 합산 WAPE는 절대오차 합계 / 실제값 합계입니다.
- 최종 모델의 고정 비중: Extra Trees 0.2675427911011525 + 보정 앙상블 0.7324572088988475. 이번 실험에서 구성 예측기와 보정 절차도 새로 학습합니다.
- 연구 코드는 `research/rebuild/`, 화면용 결과와 실제값·예측값 CSV 및 상세 방법은 `public/research/`에 있습니다. 각 결과의 출처와 재현 조건은 해당 폴더의 방법 문서를 확인하세요.
- 학습 실행 환경은 GitHub Actions의 Linux CPU입니다. 결과 산출 이후 전체 실행 수, 공통 관측, 시간 경계와 지표 재계산을 검증합니다.

## 내 매장에서 사용하기

연구 비교와 별도로 `매장 실적 비교`, `오늘 마감`, `내일 생산`, `기록 관리` 화면을 제공합니다. 운영 기능은 기존 이식 모델 5개(최종 결합·Extra Trees·보정 앙상블·메뉴별 선택·요일 기준)를 사용합니다. 연구실의 34개 설정을 매장 데이터로 자동 재학습하는 기능은 포함하지 않습니다.

1. 상품의 생산 단위·최대 생산량을 등록합니다.
2. 실제 판매·생산·재고·폐기·이월 재고를 기록합니다.
3. 다음 날 예상 판매 P50과 생산 기준 P75를 비교합니다.
4. 예측과 생산계획을 확정하고, 다음 날 실제 기록과 비교합니다.

기록은 로그인 없이 **현재 기기의 해당 주소 브라우저**에 저장됩니다. 서버는 계산 요청으로 전달된 상태만 처리하고 매장 기록을 영구 보관하지 않습니다. 실제/예시 데이터는 분리됩니다. `전체 백업` JSON에 상품·기록·고정 예측·계획이 포함되며, `기록 관리 → 백업 복원`에서 복원할 수 있습니다.

주소별 저장소가 다릅니다. 이전 https://bread-daily-planner.vercel.app 또는 Sites 주소의 기록은 이전 주소에서 백업한 뒤 새 주소에서 복원하세요. 기존 Vercel 주소도 유지합니다.

## 앱 아이콘

전용 아이콘은 `public/brand/`에 있습니다. 내장 이미지 생성 도구로 빵과 일출을 결합한 무문자 마크를 만들고 원본에서 512·192·180·32px 크기로 축소했습니다. 생성 지시문은 `public/brand/prompt.txt`에 보존합니다. 브라우저 탭, 앱 헤더, iOS 홈 화면 아이콘과 웹앱 manifest에 적용했습니다. 앱 아이콘은 화면 아래에서 내려받을 수 있습니다. 홈 화면 추가는 지원 브라우저의 기능을 사용하며 오프라인 계산은 제공하지 않습니다.

이전 Sites/Cloudflare 전용 구현 설명은 `docs/legacy-sites-notes.md`에 보존했습니다. 현재 Vercel 실행·저장·새 연구 결과는 이 문서와 현재 코드가 기준입니다.
